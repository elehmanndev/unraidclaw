UnraidClaw 0.2.0 is the first release of this fork of UnraidClaw 0.1.34 by emaspa. It adds reading and editing an installed container's settings, rebuilt the way the Docker tab's **Apply** does, and updates from this repository instead of the original.

## Highlights

### Container settings

- `GET /api/template/:name` and `unraid_template_get` return an installed container's saved template: image, network, fixed IP, privileged mode, Extra Parameters, Post Arguments, CPU pinning, memory limit, Tailscale, and every port, path, variable, label and device. Masked values come back as `***`. See [Container settings](https://github.com/elehmanndev/unraidclaw#container-settings) in the README.
- `POST /api/template/:name/edit` and `unraid_template_edit` change any of those settings and rebuild the container. Only what the request names changes.
- The command comes from Unraid's own docker manager, through the new `scripts/docker-command` helper, so everything the Docker tab supports on the server works, including the settings app updates refuse.
- The rebuilt container is created before the running one is touched, must still be running a few seconds after it starts, and is rolled back with its last log lines when it is not. The template is backed up to `/boot/config/plugins/unraidclaw/template-backups/` and only saved once the rebuilt container checks out.
- `dryRun` returns the changes, the command with masked values redacted, and the host paths that would be created.

## Upgrade notes

- The new permissions `template:read` and `template:update` are off after upgrading. **Read Only** now includes `template:read`; `template:update` must be enabled individually or through **Full Admin**.
- The plugin now updates from `github.com/elehmanndev/unraidclaw`. Installing it over an existing UnraidClaw keeps its settings, API key, permissions and TLS certificate.
- The tool count is 57, up from 55.
