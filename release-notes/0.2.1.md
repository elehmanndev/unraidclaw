UnraidClaw 0.2.1 lets an agent read and change things inside an installed app through the app's own web API, with a key you save once on the new **App Keys** tab and the agent never sees.

## Highlights

### App APIs

- `POST /api/apps/:name/request` and `unraid_app_request` send one HTTP request to an installed container's API, such as creating an album in Immich or a proxy host in Nginx Proxy Manager. See [App APIs](https://github.com/elehmanndev/unraidclaw#app-apis) in the README.
- The server finds the container's address and port from `docker inspect` and its WebUI link. A caller never passes a host, so a request can only go to that container.
- `GET /api/apps` and `unraid_app_list` show each app's default address and whether it has a key.
- JSON answers come back parsed, text as text, binary as a size, with bodies cut off at 512 KiB. The app's own status code is part of the result.

### App Keys tab

- Save a key per app as a named header such as `x-api-key`, as `Authorization: Bearer`, or as `Authorization: Basic` with a user name.
- Keys are saved by POST with Unraid's CSRF token, stored in `/boot/config/plugins/unraidclaw/app-keys.json`, and never returned by the page or the API. They are shown as `***` in requests and removed from anything the app sends back. `Set-Cookie` is never passed back.

## Upgrade notes

- The new permissions `apps:read` and `apps:update` are off after upgrading. **Read Only** includes `apps:read`; `apps:update` must be enabled individually or through **Full Admin**. A dry run of a change also needs `apps:update`.
- A container on a macvlan network such as `br0` can only be reached when **Host access to custom networks** is enabled in Unraid's Docker settings.
- The tool count is 59, up from 57.
