UnraidClaw 0.2.9 adds Docker image housekeeping and a read-only view of which containers have image updates, so an agent can keep a server clean without pulling anything to find out. It also stops secrets in unmasked template fields from showing in previews.

## Highlights

### Docker image housekeeping

- `unraid_docker_images` (`GET /api/docker/images`) lists every image with the containers, running or stopped, that use it, and flags dangling and unused images with byte totals.
- `unraid_docker_prune_images` (`POST /api/docker/images/prune`) removes images no container references: dangling ones by default, or every unused one with `"mode": "unused"`, optionally only those older than `olderThanHours`. A dry run lists exactly what would go and the bytes it would reclaim.
- A real prune removes each image with `docker rmi`, without force and never with `docker image prune`, then checks a fresh listing and reports `verified`. It needs `docker:delete` and can run as a background job with `unraid_job_start`.

### Container update status

- `unraid_docker_update_status` (`GET /api/docker/updates`) reports per container whether an image update is available, with the local and remote digests, read from the cache Unraid's own update check writes. It says how old that cache is.
- It never pulls or contacts a registry. A missing or malformed cache, or an image the cache does not list, reports `"unknown"`.

## Security and reliability fixes

- App install and update plans, container edit previews, template views, error messages and job results no longer show a secret in clear text when the template leaves `Mask="false"` on it, such as `TUNNEL_TOKEN`. A variable or label whose name contains TOKEN, SECRET, PASSWORD, PASS, KEY, APIKEY, AUTH or CREDENTIAL, in any case, is hidden as `***` like a masked one. The container still gets the real value.

## Other changes

- OpenClaw plugin: accept a SecretRef with the store source for `apiKey` and `servers[].apiKey`, which OpenClaw 2026.9 added. Thanks to @saizero-dr for the report (#19).
- Fix the CLI refusing a flag value that starts with a dash, such as `docker create --extra-args "--gpus all"`.
- `POST /api/docker/containers` and `unraid_docker_create` accept the advanced settings of Unraid's container form: `extraArgs`, `postArgs`, `staticIp`, `privileged`, `cpuset` and `devices`, each saved to the container's template. Thanks to @totalanni for the implementation this builds on.

## Upgrade notes

- No new permissions. Listing images and update status needs `docker:read`; pruning needs `docker:delete`.
- Values under secret-looking names now show as `***` in previews even when they are harmless, such as `AUTH_ENABLED=true`.
