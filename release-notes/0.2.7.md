UnraidClaw 0.2.7 lets an agent update any container, including the privileged ones and ones with Extra Parameters or devices that app updates refuse.

## Highlights

### Updates through container edits

- `unraid_template_edit` and `POST /api/template/:name/edit` take `"pull": true`: the newest image for the template's tag is pulled first, and the container is rebuilt on it with Unraid's own command and the usual swap and rollback. See [Container settings](https://github.com/elehmanndev/unraidclaw#container-settings) in the README.
- With no other change it is an update, and nothing happens when the image is already the newest.
- An update that changes no setting leaves the template file exactly as it is.
- `unraid_ca_update` refusals now say to use it, and it runs as a background job like any edit.

## Upgrade notes

- Nothing to configure. It uses the existing `template:update` permission.
