UnraidClaw 0.2.6 adds background jobs, so an agent can start a long install, update or redeploy, answer straight away, and let an Unraid notification say when it is done.

## Highlights

### Background jobs

- `unraid_job_start` and `POST /api/jobs` run an app install or update, a container edit, a compose action or edit, or a plugin install or update in the background and return the job's ID at once. See [Background jobs](https://github.com/elehmanndev/unraidclaw#background-jobs) in the README.
- A job runs the same tool and the same route a direct call would, with the caller's key, so every permission, check and log entry is the same.
- `unraid_job_get` and `unraid_job_list` read jobs back with their status, duration and result or error.
- When a job finishes, an Unraid notification says so, which reaches a phone when Unraid's notification agents are set up. It needs `notification:create`.

## Upgrade notes

- The new permissions `jobs:read` and `jobs:create` are off after upgrading. **Read Only** includes `jobs:read`.
- Jobs are kept in memory: the last 50 finished jobs, until the service restarts.
- The tool count is 66, up from 63.
