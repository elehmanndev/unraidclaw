UnraidClaw 0.3.1 fixes image housekeeping on Docker 29, where the old image an update leaves behind was invisible to the image tools and never pruned.

## Security and reliability fixes

- `GET /api/docker/images` and `POST /api/docker/images/prune` now see the untagged image an update pull leaves behind. With the containerd image store used by Docker 29 on Unraid 7.3, such an image keeps its digest and is hidden from a plain `docker image ls`, so `unraid_docker_images` reported no dangling images while the Docker tab listed them as orphans, and `unraid_docker_prune_images` never removed them. The listing now also asks for dangling images explicitly. Intermediate build layers are still left out, since other images depend on them.

## Upgrade notes

- The first dangling prune after upgrading can reclaim much more space than usual, since it removes the old images every earlier update left in `docker.img`.
