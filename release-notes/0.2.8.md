UnraidClaw 0.2.8 adds a setup profile, so every new app install follows the owner's own conventions without being told each time.

## Highlights

### Setup profile

- The profile holds the values an install fills in when the request leaves a field unset: variables such as `TZ`, `PUID`, `PGID` and `UMASK` by name, host folders by the path inside the container, such as `/media`, and an appdata folder that template defaults under any pool's `appdata` move to. See [Setup profile](https://github.com/elehmanndev/unraidclaw#setup-profile) in the README.
- `unraid_ca_install` applies it to plain and full installs. The plan lists every field it filled and the default it replaced, so a dry run shows exactly what changed. Values passed in `overrides` always win, and `"useProfile": false` installs with the template's defaults.
- `notes` hold the owner's conventions in their own words, such as how apps are exposed, for an agent to follow. Nothing applies them.
- `unraid_profile_get` also suggests a profile from the containers already installed, with the counts behind it, and points out containers whose timezone differs from Unraid's.
- `unraid_profile_update` changes it: only the fields and keys given change, `null` removes one, and `dryRun` shows the result without saving it.

## Upgrade notes

- The new permissions `profile:read` and `profile:update` are off after upgrading. **Read Only** includes `profile:read`.
- The profile starts empty, so installs behave as before until one is saved.
