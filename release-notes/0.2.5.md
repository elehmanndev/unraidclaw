UnraidClaw 0.2.5 adds Docker Compose stacks: see them, restart them, and edit and redeploy the ones that are not deployed from git, with the same backup and rollback as a container edit.

## Highlights

### Compose stacks

- `unraid_compose_list` and `GET /api/compose` list every stack from its containers' Compose labels, with its services and state. A stack deployed from inside a webhook container is found at its real place on the host. See [Compose stacks](https://github.com/elehmanndev/unraidclaw#compose-stacks) in the README.
- `unraid_compose_get` returns a stack's compose files with secrets and `.env` values shown as `***`, and the `.env` keys without values.
- `unraid_compose_action` starts, stops or restarts any stack's services, and pulls or redeploys local ones.
- `unraid_compose_edit` replaces a local stack's compose file. A value left as `***` keeps its real value. Compose checks the file first; the old one is backed up; a service that does not come back up means the old file is put back and redeployed, with its logs returned.
- A stack whose directory is a git checkout is deployed from its repository, so it can only be started, stopped and restarted here.

## Upgrade notes

- The new permissions `compose:read` and `compose:update` are off after upgrading. **Read Only** includes `compose:read`.
- Compose runs in a throwaway `docker:29.5.2-cli` container, which is pulled on first use.
- The tool count is 63, up from 59.
