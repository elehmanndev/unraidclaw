UnraidClaw 0.3.2 lets agents reach the API of Sonarr, Radarr and other apps that only answer to host names they know.

## Security and reliability fixes

- `POST /api/apps/:name/request` (`unraid_app_request`) now sends a request to the port the host publishes for the app when it has one, on `127.0.0.1` for a binding on all addresses or on the bound IPv4 address, and to the container IP only when the port is not published. Sonarr and Radarr reject a request addressed to the container IP with `400 Invalid Hostname`, so they could not be called before, even with a key saved on **App Keys**. Host-network containers are unchanged.
- `GET /api/apps` reports the same address in `baseUrl`.

## Upgrade notes

- Apps with a published port are now called on that port instead of the container IP. Responses do not change, but `url` in the result and `baseUrl` in the app list show the new address.
